**التاريخ:** ٣٠ أغسطس ٢٠٢٦
**الإصدار المستهدف:** 2.2.0
**الحالة:** معتمدة

## ١. السياق والقيود

### القيود الحاكمة

| القيد | الأثر على التصميم |
|---|---|
| **إنترنت المحل ضعيف ومتقطّع** | التنزيل يجب أن يُستأنف، والفشل يجب أن يكون صامتاً، و٧٥ ميجا لا تُنزَّل بلا موافقة صريحة |
| **حجم التطبيق ٧٥ ميجا** | لا تنزيل تلقائي أبداً. الحجم يُعرَض على المستخدم قبل الموافقة |
| **بيانات محل حقيقية** | نسخة احتياطية قبل التثبيت، والإصدار القديم يبقى للرجوع |
| **المستودع عام** | لا مفتاح دخول مدفون في الـexe — التنزيل بلا مصادقة |
| **لا توقيع رقمي** | البصمة تحمي من التلف لا من الاختراق. يُصرَّح بهذا الحدّ |

### حقائق متحقَّق منها عملياً

**استبدال التطبيق لنفسه على ويندوز** — جُرّب على `Debt-Manager.exe` وهو يعمل:

| العملية | النتيجة |
|---|---|
| الكتابة فوق exe شغّال | ✗ مرفوضة (الملف مقفول) |
| **إعادة تسمية exe شغّال** | ✅ **مسموحة** |
| وضع ملف جديد مكان الاسم الأصلي | ✅ مسموحة |
| حذف القديم بعد الإغلاق | ✅ مسموحة |

**النتيجة المعمارية:** لا حاجة لبرنامج تحديث منفصل ولا لسكربت مساعد.
إعادة تسمية + استبدال، والحذف عند الإقلاع التالي.

**واجهة GitHub** — فُحصت على مستودع عام حقيقي:

- الحقول المتاحة: `tag_name` · `published_at` · `body` (ملاحظات الإصدار) ·
  `assets[].name` و `.size` و `.browser_download_url`
- حدّ الطلبات بلا مصادقة: **٦٠ في الساعة لكل عنوان IP**
- `Accept-Ranges: bytes` — **استئناف التنزيل مدعوم**

### ٣.١ مصدر واحد لرقم الإصدار

رقم الإصدار مكتوب حالياً في موضعين منفصلين — `main.py:25` ونافذة «حول» —
فيسهل أن يتناقضا. `core/version.py`:

```python
__version__ = "2.2.0"
GITHUB_OWNER = "AbuDergham"
GITHUB_REPO = "Debt-Manager"
```

يستهلكه `main.py` ونافذة «حول» و`core/updater.py` و`tools/release.py`.

### ٣.٢ `core/updater.py`

منطق صرف، **لا يستورد Qt**، فيُختبر وحده.

```python
@dataclass
class ReleaseInfo:
    version: str            # "2.2.0" (بلا بادئة v)
    tag: str                # "v2.2.0"
    notes: str              # نص ملاحظات الإصدار
    download_url: str
    size_bytes: int
    checksum_url: Optional[str]

def is_newer(candidate: str, current: str) -> bool

                     owner: str, repo: str) -> Optional[ReleaseInfo]
def download_asset(url, dest, *, expected_size, progress_cb, should_cancel) -> Path
def verify_download(path, expected_size, expected_sha256) -> None
def install_update(new_exe: Path, target_exe: Path) -> Path
def cleanup_old_exe(target_exe: Path) -> bool
```

## ٤. التدفّق

### ٤.١ عند الإقلاع

1. **حذف `Debt-Manager.old.exe`** المتبقّي من تحديث سابق. نجاح الحذف دليل
   أن الإصدار الجديد أقلع بنجاح.
2. إن كان `check_updates` مفعّلاً (افتراضياً نعم): جلب JSON في **خيط خلفي**
   بمهلة ٥ ثوانٍ.
3. **عند أي فشل — صمت تام.** لا رسالة خطأ، لا تعطيل. أسباب الفشل المتوقّعة:
   لا إنترنت، مهلة، تجاوز حدّ الطلبات (403)، خطأ في التحليل.
4. إن وُجد أحدث ولم يكن مُتجاهَلاً: **سطر في شريط الحالة + عنصر قائمة مميّز.**
   **ولا نافذة تقاطع المستخدم.**

> الفحص عند كل إقلاع (لا مرة يومياً) — قرار المستخدم. الطلب بضعة كيلوبايت،
> وحدّ الـ٦٠/ساعة لا يُبلَغ إلا بستين فتحة في ساعة واحدة.

### ٤.٢ عند طلب التحديث

نافذة تعرض: الإصدار الحالي ← الجديد · تاريخ النشر · **حجم التنزيل صراحةً** ·
ملاحظات الإصدار. الأزرار: «تنزيل وتثبيت» · «لاحقاً» · «تجاهل هذا الإصدار».

### ٤.٣ التنزيل

- إلى `Debt-Manager.new.exe.part` بجانب الـexe الحالي
- شريط تقدّم بالنسبة والسرعة والوقت المتبقّي، وزر **إلغاء**
- **الاستئناف:** إن وُجد `.part` من محاولة سابقة وحجمه أصغر من المتوقّع،
  يُكمَّل عبر ترويسة `Range: bytes=N-`. مع إنترنت ضعيف، انقطاع عند ٩٠٪ يجب
  ألا يعني إعادة الـ٧٥ ميجا من الصفر.
- إن ردّ الخادم `200` بدل `206` على طلب استئناف، يُبدأ من جديد

### ٤.٤ التحقق

1. الحجم يطابق ما أعلنته الواجهة تماماً
2. SHA-256 يطابق ما في `SHA256SUMS.txt` المنشور مع الإصدار

**حدّ مُصرَّح به:** هذا يحمي من **التنزيل الناقص أو التالف** — وهو الخطر
الحقيقي مع إنترنت ضعيف. لا يحمي من اختراق حساب GitHub، لأن البصمة منشورة
بجانب الملف نفسه. الحماية من ذلك تحتاج توقيعاً رقمياً بشهادة.

### ٤.٥ التثبيت

```
١. نسخة احتياطية للبيانات      create_backup(prefix="pre-update")
٢. Debt-Manager.exe      →     Debt-Manager.old.exe
٣. Debt-Manager.new.exe  →     Debt-Manager.exe
٤. عند فشل ٣: إرجاع ٢ فوراً    (تراجع)
```

ثم: «تم التثبيت. أغلق التطبيق وافتحه من جديد.» مع زر «إعادة التشغيل الآن».
الـexe القديم يبقى حتى الإقلاع التالي كنسخة رجوع.

## ٦. النشر

`tools/release.py`:

1. يقرأ الإصدار من `core/version.py`
2. يشغّل `pytest` — **يتوقف عند أي فشل**
3. يبني الـexe عبر PyInstaller
4. يحسب SHA-256 ويكتب `SHA256SUMS.txt`
5. `gh release create v<الإصدار> dist/Debt-Manager.exe SHA256SUMS.txt`

## ٧. المخاطر والتخفيف

| الخطر | التخفيف |
|---|---|
| **انقطاع الإنترنت أثناء تنزيل ٧٥ ميجا** | استئناف عبر `Range` · التحقق من الحجم والبصمة · الملف الناقص لا يُثبَّت أبداً |
| **exe تالف يستبدل السليم** | التحقق يسبق التثبيت · القديم يبقى للرجوع · التراجع عند فشل الاستبدال |
| **التحديث يشغّل ترحيلاً على بيانات حيّة** | نسخة احتياطية قبل التثبيت · والترحيل نفسه محميّ ومتكرّر بأمان |
| **الفحص يبطّئ الإقلاع** | خيط خلفي بمهلة ٥ ثوانٍ · الواجهة لا تنتظره |
| **تجاوز حدّ الطلبات** | معالجة 403 كفشل صامت |
| **اختراق حساب GitHub** | **غير مُخفَّف** — يحتاج توقيعاً رقمياً. مُصرَّح به في ٤.٤ |

## ٨. الاختبارات

بلا شبكة حقيقية: JSON من ملفات ثابتة، وخادم HTTP محلي للتنزيل.

| الملف | يغطّي |
|---|---|
| `tests/test_updater.py` | مقارنة الإصدارات · تحليل JSON · الفشل الصامت بلا إنترنت · التنزيل والاستئناف والإلغاء · رفض الملف التالف · التثبيت والتراجع · حذف القديم |

**حالات إلزامية:** لا إنترنت → لا استثناء · مهلة → لا استثناء · 403 → لا استثناء ·
بصمة خاطئة → لا تثبيت · انقطاع ثم استئناف → ملف سليم · فشل الاستبدال → رجوع الاسم.

## ١٠. ملاحظة أمنية على النشر العام

قبل أول رفع للمستودع:

- `data/` غير متعقَّب — لا بيانات عملاء ✓
- لا أسرار ولا رموز دخول في الكود ✓
- `X/` (صور تطبيق شخص آخر، إحداها تعرض رصيداً حقيقياً) أُزيلت من التتبّع
  **ومن تاريخ git كاملاً** — الإزالة من التتبّع وحدها لا تكفي، إذ تبقى
  الملفات قابلة للاستخراج من التاريخ ✓
- رقم هاتف المطوّر في نافذة «حول» — موجود أصلاً داخل الـexe الموزَّع
